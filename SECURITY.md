# Security and responsible disclosure

Audit only source you are authorized to inspect. Do not turn a static finding into third-party exploitation. Use disposable project-owned files, mocked transports and fake secrets for reproductions.

For defects in MCP Guard, report a minimal redacted reproduction to this repository. Avoid attaching credentials or private scan results to public issues. For sensitive issues, use GitHub private vulnerability reporting if enabled; otherwise request a private channel without publishing exploit details. No guaranteed response SLA is offered for this experimental project.

For findings in another project, follow its security policy and authorized disclosure channel. Share source locations, evidence, preconditions and limitations; distinguish capability, static observation and reproduced behavior. A risky API alone is not a confirmed vulnerability.
